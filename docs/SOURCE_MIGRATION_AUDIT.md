The baseline commit transferred the text sources and configuration, including the React/TypeScript app, TanStack Start routes and generated route tree, Tailwind styles, bilingual dictionary, package manifest and Bun lockfile, Vite config, Supabase auth/client integrations, Drizzle config/schema/migrations and snapshots, tests, and project instructions. No `LICENSE` file appeared in the Lovable file manifest. No license has been invented or added.

The raw `src/integrations/lovable` and `src/integrations/supabase` modules, custom Lovable-auth startup, and Lovable Vite wrapper are not part of the current runtime. They are retained in Git history in the baseline commit, because they depend on platform auth, secrets, and an unconfigured Supabase project. The current MVP has no backend.

## Binary assets not retrieved

Lovable lists two binary files: `src/assets/hero-collage.jpg` and `public/favicon.ico`. The official file-read connector returned binary bytes as corrupted text, not a usable download. The preview URL redirects to Lovable sign-in in the connected browser. The current home page keeps the collage's visual slot and explicitly says the original collage is being recovered; no replacement image is presented as original. The favicon is also absent. The local app cannot yet be accepted as a complete visual migration until both original files are recovered and checked.
